# SRE Copilot：从零手写可观测 Agent

2026-10-30重新开始。核心代码由学习者亲手编写，助手负责原理讲解、任务拆分、代码评审和验收。

目标是构建一个能够读取指标、日志、Trace和知识资料来辅助排障的Agent，并让模型请求、工具执行、上下文与证据链能够关联、回放和评估。

每一步先读对应章节，再亲手实现一个小闭环，观察运行记录，最后解释设计取舍。书中的Python示例用于理解消息协议和循环结构，项目实现使用Go；具体模型参数与框架接口仍核对所选服务的当前文档。

## 第一份代码由你写

先亲手创建`go.mod`与`cmd/chat/main.go`，使用Go标准库完成：

1. 从本机环境读取模型接口、模型名和密钥。
2. 构造消息列表，发送一次非流式模型请求。
3. 检查HTTP状态和返回结构，输出回答。
4. 用`context`管理超时；成功和失败都记录关联标识、状态与耗时。

本步先打通模型通路，随后再加入工具循环。第一轮不需要引入数据库、Web界面或完整框架。不要把密钥或完整鉴权请求写入日志。

当前没有可运行的Agent实现，因此不以旧项目测试通过或教材读完作为本次完成证据。写出代码后，依据实际运行结果验收。

## 框架比较的依据

- [tRPC-Agent-Go](https://github.com/trpc-group/trpc-agent-go)：Go运行时、工具、Session/Memory/Knowledge与评估模块；[可观测性文档](https://github.com/trpc-group/trpc-agent-go/blob/main/docs/mkdocs/en/observability.md)给出了OpenTelemetry及后端接入示例。
- [Pi Agent Core](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md)：TypeScript状态、工具循环与事件流；[Pi Telemetry](https://github.com/earendil-works/pi/blob/main/packages/telemetry/README.md)提供后端无关契约与参考实现，实际后端需要适配。

选择依据是自己的语言基础、目标产品和愿意维护的运行机制。当前没有足够证据给出两者在所有Agent项目中的行业占有率或优劣结论；流行度不作为本项目的单独选型理由。
