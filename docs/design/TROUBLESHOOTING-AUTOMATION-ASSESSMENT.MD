# 排障自动化现状评估（2026-03-09）

> 目的：固定 2026-03-09 这一轮评估结论，作为后续设计、开发、验收的共同基线。
> 本文档不是历史报告归档，而是当前有效口径。

## 1. 背景

- 本项目已经具备 OPAR 循环、工具注册中心、知识检索、MCP 接入、记忆系统等基础能力。
- 本轮新增了以真实排障笔记为来源的评估语料，位于 `eval/corpus.json`，并配套 `eval/grade-response.js` 与 `eval/run-eval.sh`。
- 目标不再是“泛问答”或“能回答一些排障问题”，而是让 `sre-copilot` 按排障文档里的玩法稳定推进：识别意图、选择任务流、主动追材料、调用正确工具、基于证据输出结论。

## 2. 本轮结论

**结论一句话**：

当前系统更接近“带知识检索和工具调用的排障助手”，还不是“可按排障文档稳定执行的排障 playbook 引擎”。

**保留这条判断，不要回退到旧口径**：

- 不能再用“P0-P7 全部完成”“已进入稳定运维阶段”来描述当前项目状态。
- 当前主线应改为：`以评估语料为验收标准，补齐排障自动化链路`。

## 3. 现有能力

### 3.1 已具备

- OPAR 基础循环：`observe -> plan -> act -> reflect`
- 知识检索：长期记忆、语义召回、文档内容注入
- 工具底座：builtin / mcp / skill / script / shell 注册和执行
- 部分只读排查工具：知识检索、K8s 只读命令、SSH 管理、MCP 动态发现
- 评估基础设施：链路型语料、结构化 grader、dry-run/real-run 入口

### 3.2 已确认不足

- 主入口不统一：`Chat + CLI` 走 `/api/chat`，`企微 Agent 集成` 走 Orchestrator，行为不一致
- 专家对话意图过粗：只分 `question / troubleshoot / execute`
- 没有排障 playbook 模型：知识是片段，不是步骤、证据、完成条件
- 没有真正落地的“引导交互”：缺材料时不会稳定进入追问链路
- 工具调用缺少“证据门禁”：拿到哪些证据后才能下结论没有契约
- 结论输出没有固定结构：现象、证据、根因、建议、待验证项未被系统强约束

## 4. 评估标准冻结

从本轮开始，`eval/corpus.json` 不再只是题库，而是项目验收基线。

后续所有相关改动，都要回答下面五个问题：

1. 意图是否识别正确
2. 任务是否流转到正确的排障路径
3. 是否会在缺材料时先追问而不是直接猜
4. 工具是否调用正确，且顺序/参数/前置证据合理
5. 输出是否包含可验收的结论结构

## 5. 本期重点样例

以下两类样例必须被当成“设计锚点”，后续实现优先围绕它们完善：

- `26948 集群采集异常`
  - 关键不是直接回答根因，而是先要求 operator 日志、discover 指标、SM/PM 数量、对比集群材料。
  - 这类 case 检验的是 `引导交互 + 证据门禁 + 跨材料推理`。

- `CodeV 100915 进程采集问题`
  - 关键不是只会说“可能是配置问题”，而是按顺序推进：查指标、核对子配置、看进程、看日志、定位 reload/加载缺失、给验证动作。
  - 这类 case 检验的是 `任务流转 + 工具序列 + 结论收敛`。

## 6. 当前主验收路径

当前阶段，**主验收路径固定为外部服务入口 `POST /api/chat`**。

原因：

- 评估脚本当前就是通过 CLI 访问 `/api/chat`
- 这是当前最容易批量回归和落地 CI 的入口
- 企微 / Orchestrator 侧能力可以保留，但本轮不作为主验收口径

这意味着后续改造应优先保证：

- `/api/chat` 的行为先对齐评估标准
- `metadata.intentObservability / intentDecision / toolCalls / stepCount` 持续可观测
- 同一条 case 在 CLI 和 Chat 页面上的结果一致

## 7. 设计原则冻结

后续实现必须遵守以下原则：

- 先统一主入口，再谈多入口一致性
- 先把“问对问题、拿对证据”做好，再追求自动结论
- 先围绕真实排障语料建契约，再补抽象能力宣传
- 先让评估语料过线，再声明某能力“已完成”
- 设计文档、路线图、待办、验收文档必须保持同一口径

## 9. 不再采用的旧口径

以下说法视为失效，不应继续作为项目主叙事：

- “项目已整体完成，后面只是按需扩展”
- “ChatOps 管理入口仍是当前主线”
- “企微 / Chat / CLI 三入口已经稳定一致”
- “现有知识检索已经等价于排障自动化能力”
