# 通过 ChatOps / 专家对话提交 Bug 反馈

> 反馈会写入系统，管理员可在「管理台 → 用户反馈」查看；开发/Agent 可通过 `GET /api/admin/feedback` 读取并据此修改。

## 一、在哪里发（推荐专家对话）

- **专家对话页**（`/chat`）：**推荐**。在这里说「我要反馈一个 bug」或「提交反馈：…」会直接触发系统的「提交反馈」工具，写入后可在管理台查看。
- **ChatOps 控制台**（`/chatops`）：可点击快捷指令「提交 Bug 反馈」**取出模板**，复制后到**专家对话页**粘贴并发送；在 ChatOps 里发送同一段话不会走反馈工具（ChatOps 只解析管理类指令）。

## 二、怎么说才会被识别为「提交反馈」

系统在听到以下**任一关键词**时会使用「提交反馈」能力：

- 反馈、报告、report、bug、feedback、建议、投诉  
- 提交 bug、提交反馈、我要反馈、上报  

**推荐说法（可直接复制，改括号里的内容后发送）：**

```
提交反馈：标题【这里写简短标题】，类别 bug，描述：这里写复现步骤、现象、期望行为。严重程度 high，受影响组件：chatops
```

或更短：

```
我要反馈一个 bug：标题【xxx】，描述：xxx
```

**多条问题可以分条发，也可以一条里写清：**

```
提交反馈：标题【ChatOps/管理台问题汇总】类别 bug。描述：1) 删除意图识别了但删除未成功；2) 预审不友好看不出做了什么；3) 角色管理缺编辑和删除。严重程度 high，受影响组件：chatops, admin
```

## 三、可选参数（方便后续筛选）

| 参数         | 说明           | 示例                    |
|--------------|----------------|-------------------------|
| 标题         | 必填，简短概括 | 【切换用户弹窗白屏】    |
| 描述         | 必填，详细说明 | 复现步骤、现象、期望    |
| 类别         | 选填           | bug / feature / improvement / question |
| 严重程度     | 选填           | critical / high / medium / low        |
| 受影响组件   | 选填           | chatops、admin、专家对话、memory 等    |

## 四、提交后

- 对话里会收到「反馈已成功提交」和一条 `feedbackId`。
- 管理员在 **管理台 → 用户反馈** 可看到列表与详情，并可更新状态（待处理/处理中/已解决等）。
- 开发或 Agent 可通过接口读取并按反馈修改：

  ```bash
  curl -H "Authorization: Bearer <ADMIN_TOKEN>" "https://<你的域名>/api/admin/feedback?limit=50"
  ```

 返回的 `items` 中每条包含：`id`、`title`、`content`、`reportedBy`、`createdAt`、`feedbackId`、`category`、`severity`、`affectedComponent`、`status`。

---

**总结：在 ChatOps 或专家对话里输入「提交反馈：标题【xxx】，描述：xxx」即可；多条问题可写在一个描述里，或分多条反馈发送。**
